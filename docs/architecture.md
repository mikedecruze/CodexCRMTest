# Architecture

Trove Phase 1–2 is a React 19 / TypeScript application, scaffolded with Microsoft create-rayfin 1.36.2 (todoapp). A same-origin Node/Express API provides a working local vertical slice with persistent SQLite synthetic records. Domain invariants and authorization execute on the server, inside database transactions, never only in React. UUIDs identify records; timestamps and an append-only audit trail track mutations. `shared/types.ts` defines the client boundary. The UI is separated into page modules, reusable forms, master-record drawers, graphs and UI primitives.

The local API is a deliberate development adapter, not a claimed Fabric database or deployed Function. The Rayfin schema uses installed, supported TC39 decorators and explicit junction entities. Direct client access to those future tables is denied until a reviewed server-side authorization/transaction strategy is deployed. No production Fabric identifiers have been invented. See fabric-integration.md for the remaining deployment boundary.

The API authenticates opaque, hashed, expiring cookie sessions. Demo personas are available only with explicit TROVE_DEMO=1 outside production. Entra uses server-side OIDC authorization code + PKCE, state and nonce validation, tenant/audience/signature verification through openid-client; it requires an actual tenant registration. Source data remains synthetic in either mode. Historical financials run against a mock read-only source; contracts, activities and recurrence remain deferred.

Phase 2 adds `server/financial` for schema migration, definitions/calendars, temporal resolution, read-only mock source ingestion and HTTP routes. `shared/financial.ts` describes the API. React financial components, group Financial Overview, portfolio Reporting and financial Administration consume only server-authorized data. Seed versioning adds synthetic financial history once to existing demo databases and preserves user records and overrides. Imported and override history are immutable. The local adapter/Fabric deployment boundary remains explicit.
